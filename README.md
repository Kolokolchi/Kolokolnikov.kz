# Korney Kolokolnikov — портфолио

[Открыть сайт на GitHub Pages](https://kolokolchi.github.io/Kolokolnikov.kz/) · [Репозиторий](https://github.com/Kolokolchi/Kolokolnikov.kz)

## GitHub Pages

Каждый push в `main` запускает `.github/workflows/pages.yml`: проверку материалов, статический экспорт и публикацию сайта. Установка зависимостей для этого экспорта не требуется. Локально: `npm run build:github`; готовые файлы находятся в `out/github-pages/`.

В версии GitHub Pages демонстрации открывают исходные опубликованные сайты Ankor и «Леса-вышки». Панель управления остаётся на сервере Sites. Экспорт не меняет серверную версию, загруженные проекты или исходные материалы в `public/`.

Портфолио, видеоработы и собственное пространство для демонстрации сайтов. Публичная часть находится в `public/`; панель `/admin/` и API работают на сервере Sites. Файлы загруженных сайтов хранятся в R2, проекты и версии — в D1. Повторная публикация портфолио не удаляет загруженные версии.

## Через панель

1. Откройте `/admin/` или ссылку «Управление» внизу главной страницы. Войдите через свой аккаунт ChatGPT.
2. Нажмите «Добавить сайт» или «Загрузить версию» у существующего проекта.
3. Укажите название, адрес (`ankor`, `client-site` и т. п.) и название варианта.
4. Выберите ZIP готовой сборки. В корне архива или в единственной папке внутри него должен быть `index.html`.
5. Нажмите «Загрузить черновик», затем «Посмотреть». Черновик доступен только владельцу.
6. «Сделать основной» публикует вариант по постоянной ссылке `/demos/<адрес>/`. «Опубликовать вариант» открывает отдельный вариант, сохраняя текущий основной сайт.

У каждой версии есть постоянный адрес `/demos/<адрес>/v/<id>/`. Версии неизменяемые: для правок загружается следующая сборка. Любую завершённую версию можно снова назначить основной. «Скрыть проект» закрывает все его варианты для посетителей и убирает проект из каталога. Владелец сохраняет возможность просмотра.

Лимиты: ZIP до 100 МиБ; до 2 000 файлов; до 25 МиБ на файл; до 250 МиБ после распаковки. ZIP без пароля, методы Store/Deflate, без ZIP64 и символических ссылок. Архив проверяется и распаковывается в браузере, файлы загружаются последовательно с контрольными суммами. Неполная загрузка не меняет текущую версию. При сетевой ошибке в открытой форме можно повторить загрузку.

Загружаются готовые статические сайты владельца. Их HTML и JavaScript выполняются на домене портфолио, поэтому панель предназначена для собственных доверенных сборок. Исходники серверов, базы данных, API и серверный рендеринг этим импортом не разворачиваются. Для приложений с роутером настройте базовый путь сборки; поле «Прежний базовый путь» адаптирует ссылки старого размещения. SPA-маршруты без расширения имеют fallback на `index.html`.

## Из любого чата Codex на этом компьютере

Навык установлен в `C:\Users\Kolok\.codex\skills\portfolio-publish\SKILL.md`. Его переносимая копия лежит в `skills/portfolio-publish/` этого репозитория.

В чате разрабатываемого сайта напишите:

> Используй $portfolio-publish. Опубликуй этот сайт в моём портфолио как новый вариант. Сохрани предыдущую версию.

Для черновика уточните «загрузи черновиком». Если уже открытый чат не видит новый навык, укажите полный путь к `SKILL.md` и попросите применить его. Новый чат сможет обнаружить навык из каталога навыков.

Навык собирает исходный проект, проверяет готовые файлы и вызывает `scripts/publish-demo.mjs`. Публикация выполняется через API портфолио; переход в этот чат и публикация демо на GitHub не нужны. Код исходного проекта не копируется в репозиторий портфолио.

Служебный ключ хранится в `C:\Users\Kolok\.codex\portfolio-publisher\connection.json` в зашифрованном виде Windows DPAPI, привязанном к текущей учётной записи Windows. Его нельзя переносить на другой компьютер простым копированием. Ключ не находится в проекте, браузерном коде или навыке. Для закрытой публикации навык также получает актуальный служебный доступ через Sites `get_site` и передаёт его только через скрытый stdin. Значения ключей не выводятся.

Проверка сборки без публикации:

```powershell
node scripts/publish-demo.mjs --from 'D:\Projects\Client\dist' --id client-site --title 'Клиент' --dry-run
```

Публикация для Codex:

```powershell
node scripts/publish-demo.mjs --from 'D:\Projects\Client\dist' --id client-site --title 'Клиент' --version 'Вариант 2'
```

Команда ждёт скрытую JSON-строку с `siteToken` из Sites. Не вставляйте токены в аргументы команды. `--draft` оставляет черновик; `--list` показывает проекты; `--base-path /old-site/` адаптирует прежний префикс. При ошибке ID загрузки выводится отдельно: повтор с тем же `--upload-id` и той же сборкой продолжит операцию. По завершении скрипт читает состояние сервера и возвращает ссылки. `npm run demo:publish -- ...` и `npm run demo:import -- ...` — алиасы этого инструмента.

## Доступ

Сейчас публикация Sites доступна владельцу. Публикация версии в панели не меняет аудиторию хостинга. Для просмотра заказчиками требуется отдельно открыть доступ к самому сайту. Панель и операции управления сохраняют отдельную проверку владельца, даже если портфолио станет публичным.

Первый вход владельца проверяется по подтверждённой платформой почте `PORTFOLIO_OWNER_EMAIL`, затем в D1 сохраняется устойчивый идентификатор пользователя этого сайта. Остальные аккаунты не получают доступ к панели. Серверный `PORTFOLIO_UPLOAD_KEY` даёт издателю доступ к API независимо от браузерной сессии; у закрытого сайта дополнительно действует входной контроль Sites. Изменения из браузера проверяют Origin.

## Разработка и публикация портфолио

```powershell
cd D:\Anti-Gravity\Kolokolnikov.kz\portfolio
npm run dev -- --port 5186 --hostname 127.0.0.1
```

Локальный вход: `/signin-with-chatgpt?return_to=/admin/`. Тестовая личность `local_seedy` существует только в dev-сборке. В продакшене вход обслуживает Sites.

`npm run build` проверяет публичные файлы, генерирует логотипы и собирает Worker. `npx tsc --noEmit` проверяет TypeScript. При изменении схемы выполните `npm run db:generate`, проверьте SQL и примените новую миграцию локально через Wrangler с `dist/server/wrangler.json` и `.wrangler/state`. Sites применяет миграции продакшена при публикации. Уже применённые миграции не редактируются.

Manifest `.openai/hosting.json` сохраняет проект `appgprj_6ad1e5d56cc48191a272e249c92ef477`, bindings `DB` и `BUCKET`. Публикация серверной сборки выполняется через Sites workflow. Это уже не самостоятельная папка для статического хостинга. `dist/`, `.wrangler/`, `.sites-runtime/` и `.dev.vars` — локальные генерируемые данные, они не входят в исходники. Windows npm запускается через PowerShell: при ошибке штатного helper с `npm-prefix.js` используется `npm run build` с тем же проверенным скриптом сборки.

## Публичные материалы

`public/projects.js` — девять кейсов; `public/videos.js` — восемь видеоработ. Ankor и «Леса-вышки» загружены как первые версии; остальные кейсы пока используют прежние адреса. Подготовка комментария открывает почтовую программу, серверной отправки писем нет.

Первый логотип сохранён. `scripts/brand.mjs` генерирует три версии из одинаковых четырёх контуров. Синий отвечает за просмотр, лаймовый — за демонстрации и публикацию, оранжевый — за связь и управление. Шрифты Manrope и Unbounded размещены локально. Источники проектов, видео и логотипов описаны в `CONTENT-SOURCES.md`.

Объёмный знак первого экрана находится в `src/hero-scene.js`: фаски и толщина построены по тем же четырём контурам. `npm run build:hero` собирает локальный Three.js в `public/hero-scene.js`; готовый модуль и лицензия входят в исходники для экспорта GitHub Pages без установки зависимостей. Общая сборка обновляет его автоматически. Один котик с несколькими случайными позами нарисован в `public/cat-drawings.js`; маршрут из трёх лапок, затухание и маски за краями элементов управляются в `public/scroll-cat.js` и `public/scroll-cat.css`.
