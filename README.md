## GitHub Pages

Каждый push в `main` запускает `.github/workflows/pages.yml`: проверку материалов, статический экспорт и публикацию сайта. Установка зависимостей для этого экспорта не требуется. Локально: `npm run build:github`; готовые файлы находятся в `out/github-pages/`.

### SEO и индексация

Кейсы и видео отрисовываются в браузере из `public/projects.js` и `public/videos.js`. Для поисковиков `scripts/build-seo.mjs` собирает из тех же данных статические страницы: `projects/` (хаб) и `projects/<id>/`, `video/` и `video/<id>/`, `404.html`, `sitemap.xml`, `robots.txt`. В `index.html` и `brand.html` генератор заполняет блок между `<!-- seo:start -->` и `<!-- seo:end -->`: title, description, canonical, Open Graph, Twitter, JSON-LD. Тексты этих двух страниц лежат в `STATIC_PAGES` внутри скрипта. Старые адреса `project.html?project=` и `video.html?video=` перенаправляют на новые.

- После правки `projects.js`/`videos.js` выполните `npm run build:seo`. В CI и в `npm run build` генератор запускается сам. `scripts/check.mjs` проверяет страницы: один H1, длины title (до 60) и description (120–160), canonical, OG, JSON-LD и соответствие sitemap.
- Картинки для превью в соцсетях (1200×630) лежат в `public/assets/og/` и создаются локально: `npm run build:og [id …]`. Нужен Playwright: по умолчанию берётся из `D:\Anti-Gravity\kinetic-equipment-matrix`, другой путь задаётся в `PLAYWRIGHT_MODULE`. Если карточки нет, превью строится по скриншоту кейса.
- Боевой адрес задаётся переменной репозитория `SITE_URL` (Settings → Secrets and variables → Actions → Variables). Если она пустая, используется `https://kolokolchi.github.io/Kolokolnikov.kz/`. `GOOGLE_SITE_VERIFICATION` и `YANDEX_VERIFICATION` добавляют на главную метатеги подтверждения Search Console и Яндекс.Вебмастера.
- Серверная копия на Sites отдаёт `X-Robots-Tag: noindex, nofollow` (`build/sites-worker.ts`): это дубль портфолио и клиентские демо.

В версии GitHub Pages демонстрации открывают исходные опубликованные сайты Ankor и «Леса-вышки». API публикации демонстраций остаётся на сервере Sites. Экспорт не меняет серверную версию, загруженные проекты или исходные материалы в `public/`.

Портфолио, видеоработы и собственное пространство для демонстрации сайтов. Публичная часть находится в `public/`; API публикации демонстраций (`/api/portfolio/`) и раздел `/demos/` работают на сервере Sites. Файлы загруженных сайтов хранятся в R2, проекты и версии — в D1. Повторная публикация портфолио не удаляет загруженные версии.

Веб-панели управления (`/admin/`) больше нет: она удалена 10.11.2026, копия лежит в `notes/removed-admin-2026-11-10/`. Демонстрации публикуются из Codex (ниже).

## Демонстрации

У каждой версии есть постоянный адрес `/demos/<адрес>/v/<id>/`; `/demos/<адрес>/` открывает основную. Версии неизменяемые: для правок загружается следующая сборка. API умеет назначать основной любую завершённую версию (`POST /api/portfolio/projects/<адрес>/publish`) и скрывать проект (`PATCH /api/portfolio/projects/<адрес>/` с `{"hidden": true}`); скрытый проект закрыт для посетителей и убран из каталога, владелец сохраняет просмотр.

Лимиты: до 2 000 файлов; до 25 МиБ на файл; до 250 МиБ на сборку. Файлы загружаются последовательно с контрольными суммами. Неполная загрузка не меняет текущую версию.

Загружаются готовые статические сайты владельца. Их HTML и JavaScript выполняются на домене портфолио, поэтому публикация предназначена только для собственных доверенных сборок. Исходники серверов, базы данных, API и серверный рендеринг этим импортом не разворачиваются. Для приложений с роутером настройте базовый путь сборки; поле «Прежний базовый путь» адаптирует ссылки старого размещения. SPA-маршруты без расширения имеют fallback на `index.html`.

## Из любого чата Codex на этом компьютере

Навык установлен в `C:\Users\Kolok\.codex\skills\portfolio-publish\SKILL.md`. Его переносимая копия лежит в `skills/portfolio-publish/` этого репозитория.

В чате разрабатываемого сайта напишите:

> Используй $portfolio-publish. Опубликуй этот сайт в моём портфолио как новый вариант. Сохрани предыдущую версию.

Для черновика уточните «загрузи черновиком». Если уже открытый чат не видит новый навык, укажите полный путь к `SKILL.md` и попросите применить его. Новый чат сможет обнаружить навык из каталога навыков.

Навык собирает исходный проект, проверяет готовые файлы и вызывает `scripts/publish-demo.mjs`. Публикация выполняется через API портфолио; переход в этот чат и публикация демо на GitHub не нужны. Код исходного проекта не копируется в репозиторий портфолио.

Служебный ключ хранится в `C:\Users\Kolok\.codex\portfolio-publisher\connection.json` в зашифрованном виде Windows DPAPI, привязанном к текущей учётной записи Windows. Его нельзя переносить на другой компьютер простым копированием. Ключ не находится в проекте, браузерном коде или навыке. Для закрытой публикации навык также получает актуальный служебный доступ через Sites `get_site` и передаёт его только через скрытый stdin. Значения ключей не выводятся.

Проверка сборки без публикации:

```powershell
node scripts/publish-demo.mjs --from 'D:\Projects\Client\dist' --id client-site --title 'Клиент' --dry-run
```

Публикация для Codex:

```powershell
node scripts/publish-demo.mjs --from 'D:\Projects\Client\dist' --id client-site --title 'Клиент' --version 'Вариант 2'
```

Команда ждёт скрытую JSON-строку с `siteToken` из Sites. Не вставляйте токены в аргументы команды. `--draft` оставляет черновик; `--list` показывает проекты; `--base-path /old-site/` адаптирует прежний префикс. `--title` и `--description` необязательны: без них существующий проект сохраняет свои название и описание, новый получает название по адресу. `--delete-version <id>` удаляет версию (файлы из R2 и записи из D1; основную версию сервер удалить не даст) — так убираются и оборванные загрузки; `--unpublish-version <id>` возвращает опубликованный вариант в черновики. При ошибке ID загрузки выводится отдельно: повтор с тем же `--upload-id` и той же сборкой продолжит операцию. По завершении скрипт читает состояние сервера и возвращает ссылки. `npm run demo:publish -- ...` и `npm run demo:import -- ...` — алиасы этого инструмента.

## Доступ

Сейчас публикация Sites доступна владельцу. Публикация версии не меняет аудиторию хостинга. Для просмотра заказчиками требуется отдельно открыть доступ к самому сайту. Операции управления сохраняют отдельную проверку владельца, даже если портфолио станет публичным.

Первый вход владельца (через ChatGPT на сайте) проверяется по подтверждённой платформой почте `PORTFOLIO_OWNER_EMAIL`. После этого в D1 сохраняется устойчивый идентификатор пользователя этого сайта, остальные аккаунты доступа не получают. Вход в браузере нужен только для **просмотра** черновиков и скрытых проектов: сессия владельца работает только на чтение (GET/HEAD).

API управления (загрузка, публикация, скрытие, удаление версий) принимает только серверный ключ издателя `PORTFOLIO_UPLOAD_KEY` в заголовке `X-Portfolio-Key`, который отправляет `scripts/publish-demo.mjs`. Причина — загруженные демонстрации выполняют свои скрипты на домене портфолио. Если бы браузерная сессия давала права на управление, скрипт любого демо (включая чужие счётчики и виджеты в клиентской сборке) мог бы удалить или подменить версии, пока владелец его смотрит. Теперь такой скрипт в худшем случае прочитает другие черновики, открытые владельцу. Полная изоляция возможна только через отдельный домен для `/demos/`. CSP `sandbox` не подходит: он ломает localStorage и cookies в демо и не даёт открывать черновики. У закрытого сайта дополнительно действует входной контроль Sites.

## Разработка и публикация портфолио

```powershell
cd D:\Anti-Gravity\Kolokolnikov.kz\portfolio
npm run dev -- --port 5186 --hostname 127.0.0.1
```

Локальный вход (просмотр черновиков): `/signin-with-chatgpt?return_to=/demos/`. Тестовая личность `local_seedy` существует только в dev-сборке. В продакшене вход обслуживает Sites.

`npm run build` проверяет публичные файлы, контраст (APCA) и типы TypeScript, генерирует логотипы и собирает Worker. `npm run check` запускает все проверки без сборки: материалы, APCA, `tsc --noEmit` и ESLint. При изменении схемы выполните `npm run db:generate`, проверьте SQL и примените новую миграцию локально через Wrangler с `dist/server/wrangler.json` и `.wrangler/state`. Sites применяет миграции продакшена при публикации. Уже применённые миграции не редактируются.

Manifest `.openai/hosting.json` сохраняет проект `appgprj_6ad1e5d56cc48191a272e249c92ef477`, bindings `DB` и `BUCKET`. Публикация серверной сборки выполняется через Sites workflow. Это уже не самостоятельная папка для статического хостинга. `dist/`, `.wrangler/`, `.sites-runtime/` и `.dev.vars` — локальные генерируемые данные, они не входят в исходники. Windows npm запускается через PowerShell: при ошибке штатного helper с `npm-prefix.js` используется `npm run build` с тем же проверенным скриптом сборки.

## Публичные материалы

`public/projects.js` — четырнадцать кейсов (23.11.2026); `public/videos.js` — восемь видеоработ. Ankor и «Леса-вышки» загружены как первые версии; остальные кейсы пока используют прежние адреса. Подготовка комментария открывает почтовую программу, серверной отправки писем нет.

Первый логотип сохранён. `scripts/brand.mjs` генерирует три версии из одинаковых четырёх контуров. Синий отвечает за просмотр, лаймовый — за демонстрации и публикацию, оранжевый — за связь и управление. Шрифты Manrope и Unbounded размещены локально. Источники проектов, видео и логотипов описаны в `CONTENT-SOURCES.md`.

Объёмный знак первого экрана находится в `src/hero-scene.js`: фаски и толщина построены по тем же четырём контурам. `npm run build:hero` собирает локальный Three.js в `public/hero-scene.js`; готовый модуль и лицензия входят в исходники для экспорта GitHub Pages без установки зависимостей. Общая сборка обновляет его автоматически. Один котик с несколькими случайными позами нарисован в `public/cat-drawings.js`; маршрут из трёх лапок, затухание и маски за краями элементов управляются в `public/scroll-cat.js` и `public/scroll-cat.css`.
