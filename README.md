# Korney Kolokolnikov — портфолио

Персональный сайт с реальными проектами, страницами кейсов, презентациями для заказчиков и единой системой логотипов.

## Запуск

Требуется Node.js. Клиентских зависимостей и установки npm-пакетов нет.

```powershell
cd D:\Anti-Gravity\Kolokolnikov.kz\portfolio
npm run dev
```

Открыть http://127.0.0.1:5186. Проверка и генерация логотипов: `npm run build`.

## Страницы

- `dist/index.html` — главная, фильтры портфолио, контакты и три цвета с постоянными ролями.
- `dist/project.html?project=lesa` — кейс проекта.
- `dist/showcase.html?project=lesa` — клиентская презентация с работающим сайтом, размерами 1440 / 768 / 390 px, галереей, копированием ссылки и подготовкой комментария по почте.
- `dist/demos/` — каталог размещённых демонстраций и кнопки копирования прямых ссылок.
- `dist/demos/ankor/` и `dist/demos/lesa/` — самостоятельные сайты на том же домене, без панели портфолио.
- `dist/brand.html` — три одинаковых по геометрии логотипа и SVG для скачивания.

Ankor и «Леса-вышки» размещены внутри портфолио: их просмотр не зависит от GitHub Pages. Остальные опубликованные проекты пока открывают прежние внешние версии. Для Patrol Control показаны изображения локального прототипа без подключения к автомобилю.

## Добавление сайта для заказчика

Сначала подготовьте статическую сборку нового сайта — папку с `index.html`, CSS, JavaScript и изображениями. Затем выполните:

```powershell
npm run demo:import -- --id new-site --from 'D:\Projects\NewSite\dist' --title 'Новый сайт' --description 'Версия для согласования.'
npm run build
```

Импорт копирует готовую сборку в `dist/demos/new-site/`, адаптирует корневые ссылки на её файлы и добавляет запись в каталог. Исходный проект не изменяется. Повторный запуск с тем же `--id` обновляет демонстрацию. Если сборка предназначалась для подпапки, например `/old-site/`, укажите `--base-path /old-site/`. Для приложений с клиентским роутером настройте его базовый путь `/demos/new-site/` при сборке; автоматическая замена адресов не заменяет настройку роутера.

После публикации портфолио заказчику можно отправить:

- `https://адрес-сайта/demos/new-site/` — сам сайт на весь экран;
- `https://адрес-сайта/showcase.html?demo=new-site` — просмотр с размерами экранов и комментариями.

Кнопка «Поделиться» позволяет выбрать оба варианта. GitHub и отдельный домен для демонстрации не нужны. Запись в `projects.js` необязательна: в каталог демонстраций сайт попадает автоматически. Чтобы добавить его также в основное портфолио, создайте кейс и укажите `demoUrl: 'demos/new-site/'`.

Импорт рассчитан на статические сборки. Серверные части, базы данных и обработчики API нужно размещать отдельно либо подключать к хостингу. Локально проверьте новую демонстрацию через `npm run dev`, затем опубликуйте обновлённую папку `dist/`.

## Добавление проекта

Добавьте запись в `dist/projects.js`, изображения в `dist/assets/projects/`. `id` должен быть уникальным и состоять из латинских букв, цифр и дефисов. Категории: `website`, `product`, `presentation`.

```js
{
  id: 'new-project',
  name: 'Название проекта',
  category: 'website',
  type: 'Сайт компании',
  status: 'На согласовании',
  summary: 'Краткое описание для карточки.',
  description: 'Задача и содержание проекта.',
  features: ['Особенность проекта'],
  tags: ['Сайт', 'Дизайн'],
  image: 'assets/projects/new-project.jpg',
  url: 'https://example.com/', // null для презентации только из изображений
  repository: null,
  gallery: [{src:'assets/projects/new-project.jpg',caption:'Главный экран'}]
}
```

После публикации ссылка для заказчика: `https://адрес-сайта/showcase.html?project=new-project`.

Доступ ко всем страницам определяется настройками хостинга. Текущая публикация Sites доступна владельцу; для просмотра заказчиками нужно изменить доступ в Sites. Демо исключены из индексации через `noindex`, но это не пароль и не ограничение доступа. Индивидуальные пароли и личные кабинеты не реализованы.

Кнопка комментария составляет письмо в почтовой программе пользователя. Серверной отправки, хранения заявок или подтверждения отправки на сайте нет. Телефон, почта, WhatsApp, YouTube и GitHub указаны по данным владельца.

## Логотипы

`scripts/brand.mjs` содержит единственный набор четырёх контуров первого варианта (исходники от 13:47). Все три цветовых версии генерируются из него. Холст: 1300 × 1170; одна позиция подписи, кегль и ширина. В `dist/assets/brand/`: 6 подписанных версий для светлого и тёмного фонов, 3 цветных знака и 2 монохромных.

В соседней папке `../Tex` оставлены три исходных PNG первого варианта. Объёмный знак `dist/assets/hero-mark.png` подготовлен встроенным imagegen по синему исходнику для главного экрана; технический мастер — SVG. Три цвета используются одновременно: синий — просмотр проектов, лаймовый — презентации и работа с заказчиками, оранжевый — связь и обсуждение идеи. Manrope и Unbounded размещены локально; лицензии в `dist/assets/licenses/`.

## Публикация

Сайт работает на обычном статическом хостинге: загрузите содержимое `dist/` в корень домена. Пути демонстраций начинаются с `/demos/`; для публикации всего портфолио в подпапке нужна дополнительная настройка базовых путей. Сервер Node нужен только для локального просмотра. Manifest Sites находится в `.openai/hosting.json`.
